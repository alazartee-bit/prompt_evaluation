Here's a function that lists every object key in a bucket, using boto3's paginator to handle buckets with more than 1,000 objects.

```python
import boto3
from botocore.exceptions import ClientError, BotoCoreError


def list_s3_object_keys(bucket_name, prefix="", client=None):
    """
    Return a list of all object keys in an S3 bucket.

    Args:
        bucket_name (str): Name of the S3 bucket.
        prefix (str): Optional key prefix to filter results.
        client: Optional boto3 S3 client (useful for testing or custom config).

    Returns:
        list[str]: All object keys in the bucket.

    Raises:
        RuntimeError: If the bucket can't be listed (missing, access denied, etc.).
    """
    s3 = client or boto3.client("s3")
    keys = []

    try:
        paginator = s3.get_paginator("list_objects_v2")
        for page in paginator.paginate(Bucket=bucket_name, Prefix=prefix):
            # "Contents" is absent when a page (or the bucket) has no objects
            for obj in page.get("Contents", []):
                keys.append(obj["Key"])
    except ClientError as e:
        code = e.response.get("Error", {}).get("Code", "Unknown")
        raise RuntimeError(f"Failed to list bucket '{bucket_name}': {code}") from e
    except BotoCoreError as e:
        raise RuntimeError(f"Failed to list bucket '{bucket_name}': {e}") from e

    return keys


if __name__ == "__main__":
    for key in list_s3_object_keys("my-bucket-name"):
        print(key)
```

**How it works**

- `list_objects_v2` returns at most 1,000 keys per call. The paginator (`get_paginator("list_objects_v2")`) automatically follows `NextContinuationToken` until all pages are fetched, so you don't manage tokens yourself.
- `page.get("Contents", [])` handles empty buckets, since the `Contents` key is omitted when there are no results.
- The optional `prefix` argument lets you restrict the listing to a "folder" or key prefix.
- The optional `client` argument lets you inject a configured client (custom region, credentials, endpoint such as LocalStack, or a stubbed client for tests).

**Notes**

- Credentials come from the standard boto3 chain (environment variables, `~/.aws/credentials`, IAM role, etc.). The caller needs the `s3:ListBucket` permission.
- For very large buckets, the list can use a lot of memory. In that case, turn the function into a generator by yielding each key instead of appending to a list:

```python
def iter_s3_object_keys(bucket_name, prefix=""):
    s3 = boto3.client("s3")
    paginator = s3.get_paginator("list_objects_v2")
    for page in paginator.paginate(Bucket=bucket_name, Prefix=prefix):
        for obj in page.get("Contents", []):
            yield obj["Key"]
```

- A manual alternative to the paginator is looping on `list_objects_v2` with `ContinuationToken` while `response["IsTruncated"]` is true, but the paginator is simpler and less error-prone.

Here's a Python function using `boto3` that sends a message to an SQS queue and returns the `MessageId`:

```python
import boto3
from botocore.exceptions import ClientError, BotoCoreError


def send_sqs_message(queue_url: str, message_body: str, region_name: str = None) -> str:
    """
    Send a message to an Amazon SQS queue.

    Args:
        queue_url: The URL of the SQS queue.
        message_body: The message string to send.
        region_name: Optional AWS region. If omitted, boto3 resolves it from
                     the environment/config (or the queue URL's region).

    Returns:
        The MessageId of the sent message.

    Raises:
        ValueError: If inputs are invalid.
        RuntimeError: If the message could not be sent.
    """
    if not queue_url or not isinstance(queue_url, str):
        raise ValueError("queue_url must be a non-empty string")
    if not isinstance(message_body, str) or message_body == "":
        raise ValueError("message_body must be a non-empty string")

    try:
        sqs = boto3.client("sqs", region_name=region_name)
        response = sqs.send_message(
            QueueUrl=queue_url,
            MessageBody=message_body,
        )
        return response["MessageId"]
    except (ClientError, BotoCoreError) as e:
        raise RuntimeError(f"Failed to send message to SQS: {e}") from e


if __name__ == "__main__":
    url = "https://sqs.us-east-1.amazonaws.com/123456789012/my-queue"
    message_id = send_sqs_message(url, "Hello from Python!")
    print(f"Message sent. MessageId: {message_id}")
```

**Notes**

- **Install:** `pip install boto3`
- **Credentials:** boto3 uses the standard credential chain (environment variables, `~/.aws/credentials`, IAM role, etc.). Don't hardcode keys.
- **Region:** If you don't pass `region_name`, boto3 uses your configured default. Make sure it matches the queue's region (it's embedded in the URL, e.g. `us-east-1`).
- **FIFO queues:** If the queue URL ends in `.fifo`, you must also supply a `MessageGroupId` (and a `MessageDeduplicationId` unless content-based deduplication is enabled). You could extend the function like this:

```python
params = {"QueueUrl": queue_url, "MessageBody": message_body}
if queue_url.endswith(".fifo"):
    params["MessageGroupId"] = "default"
response = sqs.send_message(**params)
```

- **Limits:** SQS message bodies can be up to 256 KB and must contain only allowed Unicode characters.

# IAM Policy: Read-Only Access to `my-app-logs`

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowListBucket",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::my-app-logs"
    },
    {
      "Sid": "AllowGetObject",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-app-logs/*"
    }
  ]
}
```

## Why two statements?

S3 actions apply to different resource types, so the ARNs differ:

| Action | Applies to | Resource ARN |
|---|---|---|
| `s3:ListBucket` | The **bucket** itself | `arn:aws:s3:::my-app-logs` |
| `s3:GetObject` | **Objects** inside the bucket | `arn:aws:s3:::my-app-logs/*` |

A common mistake is to put both actions in one statement with only `my-app-logs/*` as the resource. In that case `ListBucket` won't work, because it's evaluated against the bucket ARN, not the object ARN.

## Optional: restrict listing to a prefix

If you want to limit access to a specific folder (e.g., `app1/`), add a condition to the list statement and narrow the object resource:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowListBucketPrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::my-app-logs",
      "Condition": {
        "StringLike": {
          "s3:prefix": "app1/*"
        }
      }
    },
    {
      "Sid": "AllowGetObjectPrefix",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-app-logs/app1/*"
    }
  ]
}
```

## Creating it with the AWS CLI

```bash
aws iam create-policy \
  --policy-name MyAppLogsReadOnly \
  --policy-document file://policy.json
```

Then attach it to a user, group, or role:

```bash
aws iam attach-role-policy \
  --role-name MyRole \
  --policy-arn arn:aws:iam::<ACCOUNT_ID>:policy/MyAppLogsReadOnly
```

## Notes
- If the objects are encrypted with a customer-managed KMS key (SSE-KMS), you'll also need `kms:Decrypt` on that key.
- Cross-account access additionally requires a matching bucket policy on `my-app-logs`.

Here are the common ways to define this lifecycle rule. All of them transition objects to **GLACIER at 90 days** and **expire (delete) them at 365 days**.

## 1. JSON (AWS CLI / API)

`lifecycle.json`
```json
{
  "Rules": [
    {
      "ID": "ArchiveToGlacierThenDelete",
      "Status": "Enabled",
      "Filter": {
        "Prefix": ""
      },
      "Transitions": [
        {
          "Days": 90,
          "StorageClass": "GLACIER"
        }
      ],
      "Expiration": {
        "Days": 365
      },
      "AbortIncompleteMultipartUpload": {
        "DaysAfterInitiation": 7
      }
    }
  ]
}
```

Apply it:
```bash
aws s3api put-bucket-lifecycle-configuration \
  --bucket my-bucket-name \
  --lifecycle-configuration file://lifecycle.json
```

## 2. Terraform

```hcl
resource "aws_s3_bucket_lifecycle_configuration" "archive" {
  bucket = aws_s3_bucket.example.id

  rule {
    id     = "archive-to-glacier-then-delete"
    status = "Enabled"

    filter {}   # applies to all objects

    transition {
      days          = 90
      storage_class = "GLACIER"
    }

    expiration {
      days = 365
    }

    abort_incomplete_multipart_upload {
      days_after_initiation = 7
    }
  }
}
```

## 3. CloudFormation (YAML)

```yaml
Resources:
  MyBucket:
    Type: AWS::S3::Bucket
    Properties:
      LifecycleConfiguration:
        Rules:
          - Id: ArchiveToGlacierThenDelete
            Status: Enabled
            Transitions:
              - TransitionInDays: 90
                StorageClass: GLACIER
            ExpirationInDays: 365
            AbortIncompleteMultipartUpload:
              DaysAfterInitiation: 7
```

## Notes

- **Days are counted from object creation**, so an object moves to Glacier at day 90 and is deleted at day 365 (it spends ~275 days in Glacier).
- **Glacier minimum storage duration is 90 days.** Because the transition happens at day 90 and deletion at day 365, you stay well above this and incur no early-deletion fees.
- **Versioned buckets:** the rule above only affects current versions. To also manage old versions, add:
  ```json
  "NoncurrentVersionTransitions": [{ "NoncurrentDays": 90, "StorageClass": "GLACIER" }],
  "NoncurrentVersionExpiration": { "NoncurrentDays": 365 }
  ```
- **Scope:** to limit the rule to a folder, change the filter to `"Filter": {"Prefix": "logs/"}`.
- `GLACIER` refers to S3 Glacier Flexible Retrieval. Use `GLACIER_IR` for Instant Retrieval or `DEEP_ARCHIVE` for Deep Archive.

Task: Write a regular expression that matches a valid AWS S3 bucket ARN such as arn:aws:s3:::my-bucket-name.

Model score: 9/10   Syntax score: 10/10

Weaknesses: Omits some newer reserved prefixes and suffixes (`sthree-`, `amzn-s3-demo-`, `--table-s3`, `--x-s3`).; Does not cover other partitions such as aws-iso.; More complex than the task needs, and it requires lookahead support, so it will not work in RE2 or POSIX engines.; The `\|` escape inside the table's inline code may look confusing when the markdown is rendered.

## Regex

```regex
^arn:aws(?:-cn|-us-gov)?:s3:::(?!(?:\d{1,3}\.){3}\d{1,3}$)(?!xn--)(?!.*\.\.)(?!.*-s3alias$)(?!.*--ol-s3$)[a-z0-9][a-z0-9.-]{1,61}[a-z0-9]$
```

## How it works

| Part | Meaning |
|---|---|
| `^arn:aws(?:-cn\|-us-gov)?` | ARN prefix with the standard, China, or GovCloud partition |
| `:s3:::` | S3 service. Region and account ID are empty for buckets. |
| `(?!(?:\d{1,3}\.){3}\d{1,3}$)` | Bucket name must not look like an IP address (e.g. `192.168.5.4`) |
| `(?!xn--)` | Must not start with `xn--` |
| `(?!.*\.\.)` | No consecutive periods |
| `(?!.*-s3alias$)(?!.*--ol-s3$)` | Must not use the reserved suffixes |
| `[a-z0-9]` | Starts with a lowercase letter or digit |
| `[a-z0-9.-]{1,61}` | Middle: lowercase letters, digits, dots, hyphens |
| `[a-z0-9]$` | Ends with a lowercase letter or digit (total length 3–63) |

## Examples

Matches:
- `arn:aws:s3:::my-bucket-name`
- `arn:aws:s3:::my.bucket.123`
- `arn:aws-cn:s3:::logs-bucket`

Doesn't match:
- `arn:aws:s3:::My_Bucket` (uppercase or underscore)
- `arn:aws:s3:::ab` (too short)
- `arn:aws:s3:::-bucket` (starts with a hyphen)
- `arn:aws:s3:::my..bucket` (consecutive periods)
- `arn:aws:s3:::192.168.5.4` (IP-address format)

## Optional: allow object ARNs too

To also accept `arn:aws:s3:::bucket/path/to/key`, replace the final `$` with `(?:/.*)?$`. The IP-address lookahead's `$` would also need to become `(?:/|$)`.

This pattern needs a regex engine with lookahead support (PCRE, JavaScript, Python `re`, Java, etc.).

Case 6 (regex): 9.0/10

Task: Write a regular expression that matches an AWS EC2 instance ID, which is 'i-' followed by either 8 or 17 lowercase hexadecimal characters.

Model score: 8/10   Syntax score: 10/10

Grader: The primary regex is fully correct and anchored, meeting both criteria. The deduction is for the misleading 'equivalent form' that is actually wrong and for the clutter, plus Python code that still has the trailing-newline flaw.

Weaknesses: It offers an 'equivalent form' that it then admits is wrong (it matches 8 or 16 characters), which is contradictory and confusing, and the form should not be labeled equivalent.; It includes unnecessary extra material, such as the wrong alternative and a Python usage section.; The Python example uses $ and match, which allows a trailing newline, even though the answer warns about this and does not fix it in the code.

**Regex:**

```
^i-(?:[0-9a-f]{8}|[0-9a-f]{17})$
```

**Explanation:**
- `^` and `$` anchor the match to the whole string, so nothing extra can come before or after the ID.
- `i-` matches the literal prefix.
- `(?:...)` is a non-capturing group containing two alternatives:
  - `[0-9a-f]{8}` matches the older 8-character ID format.
  - `[0-9a-f]{17}` matches the newer 17-character ID format.
- Because of the `$` anchor, IDs with 9–16 or more than 17 hex characters are rejected. The alternation does not allow partial matches.

**Equivalent form:**

```
^i-(?:[0-9a-f]{8}){1,2}$
```

This is wrong. It would accept 8 or 16 characters, not 17, so use the first version.

**Examples:**
- `i-1234abcd` matches (8 hex characters).
- `i-0123456789abcdef0` matches (17 hex characters).
- `i-1234ABCD` does not match (uppercase).
- `i-0123456789abcdef` does not match (16 characters).
- `i-xyz12345` does not match (non-hex characters).

**Usage in Python:**

```python
import re

pattern = re.compile(r'^i-(?:[0-9a-f]{8}|[0-9a-f]{17})$')
print(bool(pattern.match("i-0123456789abcdef0")))  # True
```

For Python, you may prefer `re.fullmatch` with the pattern without anchors, or use `\Z` in place of `$`, because `$` also matches before a trailing newline.
